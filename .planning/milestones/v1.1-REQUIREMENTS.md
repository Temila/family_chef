## v1.1 Requirements — All Validated

### WISH — 用户愿望提交与管理

- ✓ **WISH-01**: 注册用户可提交愿望，包含菜名（必填）、参考链接（可选）、备注（可选） — Phase 5
- ✓ **WISH-02**: 用户可查看自己提交的所有愿望列表及当前状态 — Phase 5
- ✓ **WISH-03**: 用户可在愿望"已上架"前编辑愿望内容（菜名/参考链接/备注） — Phase 7
- ✓ **WISH-04**: 用户可在愿望"已上架"前撤销（软删除, status='已撤销'）愿望 — Phase 7

### FLOW — 厨师认领与推进工作流

- ✓ **FLOW-01**: 管理员可查看所有愿望列表; 厨师看到 待处理队列 + 我的认领 — Phase 5
- ✓ **FLOW-02**: 厨师可"认领"待处理愿望 — 独占认领，状态变为"准备中"，该厨师成为负责人 — Phase 5
- ✓ **FLOW-03**: 认领厨师可将愿望关联到一个已上架菜品，状态变为"已上架"，愿望锁定不可修改 — Phase 5
- ✓ **FLOW-04**: 认领厨师可"拒绝"愿望，必须填写拒绝原因 — Phase 5
- ✓ **FLOW-05**: 厨师可查看"我的认领"（自己认领的愿望） — Phase 5

### PERM — 可见性与权限

- ✓ **PERM-01**: 愿望仅对提交者本人、认领该愿望的厨师 + 待处理状态下的所有厨师、管理员可见 — Phase 5
- ✓ **PERM-02**: 用户只能编辑/撤销自己的愿望 — Phase 5
- ✓ **PERM-03**: 厨师只能推进自己认领的愿望 — Phase 5
- ✓ **PERM-04**: 管理员可查看与推进所有愿望 — Phase 5

### NOTIF — 通知（续 v1.0 NOTIF-02）

- ✓ **NOTIF-03**: 愿望状态变化时（认领/准备中/已上架/已拒绝），提交者在应用内看到红点未读提示 — Phase 6
- ✓ **NOTIF-04**: 用户查看愿望详情后，红点消除 — Phase 6
- ✓ **NOTIF-05**: 新愿望提交时，飞书推送愿望信息给厨师端（复用 feishu_client） — Phase 6
- ✓ **NOTIF-06**: 愿望被用户编辑/撤销时，认领厨师收到飞书通知 — Phase 6

### UX — 移动端体验

- ✓ **UX-01**: 用户端愿望列表与提交入口移动端友好 — Phase 7
- ✓ **UX-02**: 厨师端愿望管理界面（认领/推进/拒绝）移动端友好 — Phase 7
- ✓ **UX-03**: 状态在愿望卡片上有清晰视觉标识（徽章/颜色） — Phase 7

### DATA — 数据模型（续 v1.0 DATA-05）
