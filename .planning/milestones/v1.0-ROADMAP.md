# Milestone v1.0: 访客点菜邀请

**Status:** ✅ SHIPPED 2026-05-29
**Phases:** 1-4
**Total Plans:** 6

## Overview

在现有家庭点菜系统上新增访客邀请点菜功能，从数据层到完整用户体验分四阶段交付。家庭成员可生成一次性邀请链接，来访朋友无需注册即可浏览菜品、提交订单，厨师即时收到飞书通知。

## Phases

**Goal**: 数据库结构支持访客邀请和访客订单，为后端开发解除阻塞
**Depends on**: Nothing (first phase)
**Plans**: 1 plan

Plans:
- [x] 01-01-PLAN.md — 创建 GuestInvitation 模型 + Order FK + Alembic 迁移 + 虚拟 guest 用户

**Details:**

### Phase 2: Backend Core

**Goal**: 所有邀请和访客下单 API 端到端可用
**Depends on**: Phase 1
**Plans**: 2 plans

## Milestone Summary

**Key Decisions:**
- 链接 token 使用 UUID4（不可猜测，无需额外加密）
- 访客订单复用现有 Order 模型（user_id 指向虚拟 __guest__ 用户）
- 一次性使用通过原子性事务实现（status 检查 + 订单创建 + 状态更新）
- 访客页面独立于主 SPA（绕过 AuthProvider 和 ProtectedRoute）
- 惰性过期检查（无需后台定时任务）

**Issues Resolved:**
- Guest route 重定向到登录页（React Router 多 Routes 块冲突）
- 分类筛选缺少地域→菜系联动
- 剪贴板复制在非 HTTPS 环境失败（增加 execCommand 回退）
- 空购物车提交按钮无禁用样式
- Alembic 迁移双头合并（divergent heads）
- 测试基础设施：missing tables 清理、rate limiter 持久化、PRAGMA 事务

**Issues Deferred:**
- 访客备注功能（GORD-06 已按 D-09 延期）
- GORD-06 备注字段未实现（不影响核心流程）

**Technical Debt:**
- CORS allow_origins: ["*"] 在未认证端点存在 CSRF 风险（建议后续收紧）
- guestFetch 无重试机制（家庭场景可接受）
