# Requirements Archive: v1.0 访客点菜邀请

**Status:** ✅ SHIPPED 2026-05-29
**Core Value:** 让未注册的访客通过一次性链接安全、简单地完成点菜，一次提交、即时通知厨师

## v1 Requirements

### Invitation Management

- [x] **INV-01**: Chef 角色用户可一键生成访客邀请链接（自动绑定自己为厨师） — ✓ Verified (Phase 2)
- [x] **INV-02**: User 角色用户生成邀请链接时可选择指定一位厨师 — ✓ Verified (Phase 2)
- [x] **INV-03**: 邀请链接生成后 2 小时内有效，过期自动失效 — ✓ Verified (Phase 1, 惰性过期)
- [x] **INV-04**: 用户可复制邀请链接到剪贴板 — ✓ Verified (Phase 3)
- [x] **INV-05**: 用户可通过微信/短信分享邀请链接（Web Share API + 剪贴板降级） — ✓ Verified (Phase 3)
- [x] **INV-06**: 用户可查看自己生成的邀请链接列表及状态（活跃/已使用/已过期/已撤销） — ✓ Verified (Phase 3)
- [x] **INV-07**: 用户可提前撤销尚未使用的邀请链接 — ✓ Verified (Phase 3)

### Guest Ordering

- [x] **GORD-01**: 访客通过邀请链接访问点菜页面，无需注册或登录 — ✓ Verified (Phase 2)
- [x] **GORD-02**: 访客仅能看到邀请绑定的厨师所上架的菜品（含图片、食材信息） — ✓ Verified (Phase 2)
- [x] **GORD-03**: 访客可将菜品加入购物车并设置数量 — ✓ Verified (Phase 4, UAT passed)
- [x] **GORD-04**: 访客提交订单时无需选择厨师（已绑定），直接提交 — ✓ Verified (Phase 4, UAT passed)
- [x] **GORD-05**: 一链接仅能提交一次订单，提交后链接变为只读（可查看订单内容） — ✓ Verified (Phase 2, UAT passed)
- [ ] **GORD-06**: 访客可在提交订单时可选填写备注（如忌口，最多 200 字） — ⚠ Deferred (按 D-09 决定延期至 v2)
- [x] **GORD-07**: 访客提交订单后看到确认页面，展示订单摘要 — ✓ Verified (Phase 4, UAT passed)

### Guest UX

- [x] **GUX-01**: 访客点菜页面移动端优先适配（响应式布局，适配微信内置浏览器） — ✓ Verified (Phase 4, UAT passed)
- [x] **GUX-02**: 访客点菜页面独立于主应用布局（无侧边栏、无顶部导航） — ✓ Verified (Phase 4, UAT passed)
- [x] **GUX-03**: 链接过期时显示友好的中文错误提示 — ✓ Verified (Phase 4, UAT passed)
- [x] **GUX-04**: 链接已使用时显示已提交的订单摘要（只读） — ✓ Verified (Phase 2+4, UAT passed)
- [x] **GUX-05**: 无效链接显示友好错误提示 — ✓ Verified (Phase 4, UAT passed)

### Notification

- [x] **NOTIF-01**: 访客提交订单后通过飞书通知绑定的厨师（标注为"访客订单"） — ✓ Verified (Phase 2)
- [x] **NOTIF-02**: 访客订单在厨师的订单列表中可见，带"访客"标识 — ✓ Verified (Phase 3)

### Data & Security

- [x] **DATA-01**: 邀请 token 使用 UUID4 生成，不可猜测 — ✓ Verified (Phase 1)
- [x] **DATA-02**: 邀请数据存储在独立的 guest_invitations 表中 — ✓ Verified (Phase 1)
- [x] **DATA-03**: 现有 Order 模型支持 user_id 为 NULL（访客订单）和 guest_invitation_id 外键 — ✓ Verified (Phase 1, user_id 指向 __guest__ 用户)
- [x] **DATA-04**: 一次性使用通过原子性状态检查实现 — ✓ Verified (Phase 2, 事务内 check+create+update)
- [x] **DATA-05**: 通过 Alembic 迁移变更数据库结构 — ✓ Verified (Phase 1, 可正向/回滚)
