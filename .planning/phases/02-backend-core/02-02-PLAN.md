## Phase Goal

**As a** guest with a valid invitation link, **I want to** submit a one-time order, **so that** the chef receives my order and gets notified, and I can view my order summary afterward.

<objective>
Implement guest order submission with atomic one-time enforcement, Feishu notification with guest labeling, and used-link order summary.

Purpose: Complete the second vertical slice — guest can submit an order once (no double-submit), chef gets a Feishu notification tagged as guest order, and the used link shows a read-only summary. This covers the remaining 4 Phase 2 requirements (GORD-05, DATA-04, NOTIF-01, GUX-04).
Output: Working POST /api/guest/{token}/orders and GET /api/guest/{token}/summary endpoints with Feishu guest notification support.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → POST /api/guest/{token}/orders | Unauthenticated — token-based, one-time use enforced atomically |
| Client → GET /api/guest/{token}/summary | Unauthenticated — token-based, read-only |
| Backend → Feishu API | Outbound HTTP — notification delivery, failure tolerated |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-05 | Tampering | Race condition on one-time link (double-submit) | mitigate | Atomic status check + order create + status update in single DB transaction (D-05/D-06/D-07). SQLite single-writer prevents concurrent commits |
| T-02-06 | Tampering | Guest submitting dish_id from another chef | mitigate | GuestService validates each dish_id has DishChef(chef_id == invitation.chef_id, status == "published") |
| T-02-07 | Denial of Service | Feishu notification blocking order response | mitigate | Notification wrapped in try/except with silent failure (D-10) — order succeeds regardless of notification |
| T-02-08 | Information Disclosure | Summary endpoint leaking order details | mitigate | Token required; only shows order linked to that specific invitation |
| T-02-SC | Tampering | npm/pip installs | accept | No new packages in Phase 2 |
