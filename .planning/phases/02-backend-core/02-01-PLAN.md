</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → POST /api/guest/invitations | Authenticated (JWT) — chef/user role required |
| Client → GET /api/guest/{token}/dishes | Unauthenticated — token-based access, UUID4 in path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Information Disclosure | Guest dish listing via token | mitigate | UUID4 token (122-bit entropy) makes brute-force guessing infeasible; token is single-use |
| T-02-02 | Tampering | POST /api/guest/invitations without auth | mitigate | require_role("chef", "user") dependency enforces JWT authentication + role check |
| T-02-03 | Tampering | User creating invitation with invalid chef_id | mitigate | GuestService validates chef exists, role="chef", is_active=True before creating invitation |
| T-02-04 | Information Disclosure | Guest seeing dishes from wrong chef | mitigate | Token validates against specific chef_id; dish query uses target_chef_id filter |
| T-02-SC | Tampering | npm/pip installs | accept | No new packages installed in Phase 2 (all dependencies pre-existing) |
</threat_model>
