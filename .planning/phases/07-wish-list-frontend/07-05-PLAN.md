<objective>
Close the H-3 UAT gap: deep-link highlight (`/wishes/<existing-id>`) currently fires a false "未找到该愿望" toast for every existing wish id, because the `requestSeqRef` discard under React 19 StrictMode / focus-抢占 / HMR leaves a transient `wishes=[] && loading=false` window during which the highlight effect's `if (loading) return undefined;` guard (added by CR-01, commit f9d1839) is insufficient. The Plan-03 fix was incomplete; the Plan-07-04 gap closure addressed a different blocker (migration drift) and did not touch this file.

The fix combines two defensible, additive changes per the diagnosed root cause in `.planning/debug/wish-deeplink-false-missing-toast.md`:

1. **Primary (`fetchedOnce` flag)** — only consider the wish list "loaded enough to render a missing-toast verdict" once `setWishes` has actually been called from a non-discarded `.then` path. `.finally(setLoading(false))` no longer opens the false-positive window because `fetchedOnce` remains false until the real success branch commits.
2. **Defensive (`setTimeout(100)`)** — widen the missing-toast scheduling window from `setTimeout(0)` to `setTimeout(100)` so a subsequent `setWishes` commit + cleanup can clear the timer before it fires. This protects against any other latent race introduced by future refactors.

Both changes are applied to `UserWishesPage.jsx` and `ChefWishesPage.jsx` (which `AdminWishesPage` reuses via `viewAsAdmin`). A Playwright regression script `repro_h3_regression.py` is added at the repo root to lock in the fix; it throttles `/api/wishes` to expose the race, navigates to `/wishes/1`, `/wishes/2`, `/wishes/3` for a user with at least 3 wishes, and asserts that no toast appears. The script exits non-zero on regression.

Output: 2 files modified (`UserWishesPage.jsx`, `ChefWishesPage.jsx`); 1 file added (`repro_h3_regression.py`); 1-3 commits on the `feature/guest_order` branch. The H-3 UAT gap closes when the regression script exits 0 and `npm run build` passes.
</objective>
