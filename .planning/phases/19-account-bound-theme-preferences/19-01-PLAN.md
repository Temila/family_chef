<objective>
Add the server-side persistence layer for per-user theme preferences (D-A7). One `user_theme_preferences` table keyed by user_id (PK + FK CASCADE), four fields (`active_theme` JSON, `season_enabled` BOOLEAN, `hemisphere` VARCHAR(8), `season_theme_map` JSON) plus `updated_at`, plus two REST endpoints at `/api/users/me/theme-preferences` (GET 200/404 + PUT 200 upsert). No per-field merging — server LWW replaces the entire payload (D-A1). The rendering pipeline (theme-engine, FOUC bootstrap, presets, ThemeSettingsPage body, color tokens) is NOT touched in this plan.

Purpose:  This is the source-of-truth back-end for Phase 19. Without it, Plan 02 has nowhere to PUT preferences. Once this lands, Plan 02 can dual-write localStorage + PUT, and the login-fetch + first-login-migration flow has a server to call.
