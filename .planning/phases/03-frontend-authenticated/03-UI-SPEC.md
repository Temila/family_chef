## Spacing Scale

Existing de facto scale from CSS (D-05 row layout uses 12px vertical padding matching `.list-item` pattern):

| Token | Value | Usage |
|-------|-------|-------|
| 2xs | 4px | Badge inner padding top/bottom, inline icon gaps |
| xs | 8px | Filter-chip gaps, modal-body padding sides |
| sm | 12px | Row vertical padding (matching `.list-item`), grid gaps |
| md | 16px | Section padding, card-body padding, modal-header padding |
| lg | 20px | Modal-header `h3` margin (implicit via padding) |
| xl | 24px | Profile card padding top/bottom, major section vertical breaks |
| 2xl | 32px | Large page-level gaps |
| 3xl | 48px | Not used in Phase 3 |

Exceptions:
- **Icon-only touch targets:** `40px × 40px` minimum (matches existing `.btn-icon`). WCAG 2.1 recommends 44px, but existing codebase uses 40px — maintain consistency.
- **Row list items:** Minimum 44px tap height (`.list-item` has 12px padding top/bottom × 2 + ~20px content height = 44px).

## Component Inventory (Phase 3 additions)

### 1. Invitation Section (embedded in UserHomePage, D-01)

- **Type:** Section within UserHomePage (not separate page)
- **Position:** Below the quick-action menu grid (after the `menuEntries` grid)
- **Heading:** "邀请访客" (section-title style)
- **CTA button:** "创建邀请" (btn-primary, D-12)
- **"查看全部"** link text next to heading (D-02) — opens full-screen modal

### 2. Invitation Row (D-05, D-06)

- **Layout:** Horizontal row, matching `.list-item` pattern
- **Per row content:**
  - Status badge (left-aligned, using extended Badge component)
  - Created time (formatted via `formatDate`)
  - Expiry time (formatted via `formatDate`)
  - Chef name (only for user role — hidden for chef role since chef=inviter)
  - Copy link icon (`btn-icon`, with `📋` emoji, shown only for `active` status per D-16)
  - Revoke button (`btn-sm btn-outline` with `--danger` border, shown only for `active` status per D-21)
- **Row separator:** `border-bottom: 1px solid var(--border)` (existing `.list-item` pattern)
- **Hover:** `background: var(--bg-card-hover)` (existing `.list-item:hover`)
- **Sort:** `created_at` descending (D-08)

### 3. Invitations Modal (full-screen, D-02)

- **Trigger:** "查看全部" click
- **Type:** Full-screen modal overlay (`.modal-overlay` without the default `.modal-content` width constraint; `max-width: 100%; height: 100vh`)
- **Header:** "邀请记录" + close button (×)
- **Body:** Scrollable invitation list (same row pattern as section, all rows shown)
- **Note:** "创建邀请" button NOT repeated inside modal (D-04)
- **Close:** × button + overlay click dismiss

### 4. Chef Select Modal (User role only, D-11)

- **Trigger:** "创建邀请" → User role → opens chef selection
- **Type:** Standard modal (`.modal-content`, max-width 400px)
- **Header:** "选择厨师"
- **Body:** Chef list using existing `.chef-select-item` pattern (from OrderPage chef picker — already exists in CSS at line 409)
- **Selection:** Click a chef → highlight with `active` class → auto-proceed to create
- **Empty:** "暂无可用厨师" (fallback if `getChefs()` returns empty)

### 5. Create Link Modal (D-09, D-10, D-11)

- **Trigger:** Chef → immediate create; User → after chef selection
- **Type:** Standard modal (`.modal-content`, max-width 440px)
- **Header:** "邀请链接已创建"
- **Body:**
  - Full link URL: `window.location.origin + '/guest/' + token` (truncated display with monospace style if long)
  - "2小时内有效" notice (small, muted text)
  - Two buttons side by side:
    - **"复制链接"** (`btn-primary`) — copies to clipboard + shows toast
    - **"分享"** (`btn-outline`) — calls `navigator.share()` if available; if Web Share API not supported, toasts "当前浏览器不支持分享功能，请使用复制链接"
- **Footer:** "完成" button (btn-secondary) to dismiss modal

### 6. Revoke Confirmation Dialog (D-18, D-19, D-20)

- **Trigger:** Click revoke button in row
- **Type:** Small modal (`.modal-content`, max-width 360px) or `window.confirm` pattern consistent with existing codebase. **Preference: modal** for Phase 3 to match revoke's severity.
- **Header:** "撤销邀请"
- **Body:** "确定要撤销这条邀请链接吗？撤销后邀请将立即失效，访客无法继续使用此链接点菜。"
- **Footer:** "取消" (btn-secondary) + "确定撤销" (btn-danger — uses existing `btn-outline` with `--danger` border, or new destructive variant)

### 7. Guest Order Badge (D-22, D-23, D-24)

- **ChefOrdersPage:**
  - Add `.badge-warn` with text "访客订单" next to `order-no` text inside `.order-header`
  - Only rendered when `order.is_guest === true`
  - Add filter chip "访客订单" to the filter-chips row (D-23) — connects to `filterStatus === 'guest'`
- **OrderDetailPage:**
  - Add `.badge-warn` with text "访客订单" next to the "订单 #N" heading
  - Only rendered when `order.is_guest === true`

### 8. API Client Additions (`api/client.js`)

```
getInvitations(params?)      → GET /api/guest/invitations?page=&page_size=
createInvitation(chefId?)    → POST /api/guest/invitations (+ body: { chef_id } for user role)
revokeInvitation(id)         → PUT /api/guest/invitations/{id}/revoke
```

## Interaction States

### Empty state (no invitations yet)
- **Icon:** 📭 (matches existing EmptyState default)
- **Text:** "还没有邀请记录"
- **Subtext:** "创建邀请链接，让来做客的朋友提前点好想吃的菜"

### Loading state
- Use existing `Loading` component (spinner + optional text "加载中…")

### Error state — create invitation failed
- **Toast:** `showToast('创建邀请失败，请稍后重试', 'error')`

### Error state — revoke invitation failed
- **Toast:** `showToast('撤销失败，请稍后重试', 'error')`

### Error state — load invitation list failed
- **Toast:** `showToast('加载邀请列表失败', 'error')`

### Error state — copy to clipboard failed
- **Toast:** `showToast('复制失败，请手动复制', 'error')`

### Error state — Web Share API unavailable
- **Toast:** `showToast('当前浏览器不支持分享功能，请使用复制链接', 'error')`

### Optimistic update — revoke (D-20)
- Click revoke → confirm dialog → immediately update row status to "revoked" in local state → send API request → on failure, rollback with error toast
