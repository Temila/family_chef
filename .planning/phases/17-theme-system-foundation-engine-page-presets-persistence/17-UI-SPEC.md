# Phase 17 — UI Design Contract

> Visual and interaction contract for Phase 17 — Theme System Foundation
> (Engine, Page, Presets & Persistence).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **No new visual language is introduced.** This phase promotes the build-time
> MD3 token pipeline (`scripts/generate-tokens.cjs`) to a runtime theme engine,
> adds a /theme card-grid page (card-as-preview), 5 presets, a Header entry
> button, and a backend `CustomTheme` model + per-user CRUD. Every visual
> value reuses the established MD3 design tokens in
> `frontend/src/css/tokens.css`, the existing primitive card/button/chip CSS
> that already reads `--md-*` vars, and the existing v1.2 layout system.
>
> **Phase 17 is read-only on the custom-theme side.** Phase 18 (a separate
> milestone phase) will ship the color picker, 9-variant selector, drag
> preview, create/edit/delete UI, and seasonal auto-switch. Those areas are
> explicitly out of scope for this contract.

## Spacing Scale

**Reused — no changes.** Phase 17 uses the established 8dp grid declared in
`tokens.css:151-159`. The /theme page consumes these tokens directly via the
existing `.page-container` rhythm and the standard `.grid-*` utilities.

| Token | Value | Usage in Phase 17 |
|-------|-------|-------------------|
| `--md-spacing-1` | 4px | Card chip leading-icon gap; "active" indicator inner padding |
| `--md-spacing-2` | 8px | Card body padding (preview-mini-UI internal); Chip/Button gap within card preview |
| `--md-spacing-3` | 12px | Card header padding (top + chip baseline); Card sub-element vertical gap |
| `--md-spacing-4` | 16px | Card outer padding; grid `gap`; preview surface areas |
| `--md-spacing-5` | 24px | Card-outer padding (PageContainer side margin); page top padding |
| `--md-spacing-6` | 32px | Page section vertical gap (above and below the grid) |
| `--md-spacing-7` | 40px | EmptyState vertical padding (only renders when user has zero custom themes) |
| `--md-spacing-8` | 56px | Reserved; not used in Phase 17 (Header already at 64dp via `Header.css:14`) |

**New spacing exceptions (locked):**

- `.theme-card-grid { gap: var(--md-spacing-4); }` — explicit `gap` declaration
  on the grid container (matches existing `.dish-grid` pattern at
  `styles.css:152-156`).
- `.theme-card { padding: var(--md-spacing-4); }` — outer card padding (16dp
  consistent with existing primitive card body padding).
- `.theme-card__preview { padding: var(--md-spacing-3); }` — preview mini-UI
  shell padding (12dp, slightly tighter than outer card to give the preview
  surface room to read as a contained "scene").
- `.theme-card__header { padding: var(--md-spacing-3) var(--md-spacing-4) 0; }` —
  card header: 12dp top, 16dp horizontal, 0 bottom (chip flush with preview).
- `.theme-card__active-indicator { padding: var(--md-spacing-1) var(--md-spacing-2); }` —
  small "✓ 已选中" pill: 4dp / 8dp.
- `.theme-page__topbar { padding: var(--md-spacing-5) 0 var(--md-spacing-4); }` —
  page top section: 24dp top / 16dp bottom (title + reset button row).
- `.theme-card__chip { padding: 0 var(--md-spacing-2); }` — micro chip in card
  header (kind label "预设"/"自定义"): 0 vertical / 8dp horizontal — matches

## Color

**Reused — no new color tokens introduced.** Phase 17 adds zero new colors.
The entire feature is a *runtime override surface* that maps onto the existing
MD3 token space declared in `tokens.css`. The /theme page inherits all
visual color from the active theme; the preview cards render palettes that
already exist in the token system.

### Runtime Override Surface

The generated `<style id="fc-dynamic-theme">` element appended to `<head>`
**AFTER** `tokens.css` loads emits two selector blocks:

```css
:root {
  /* ~50 semantic color roles — light scheme derived from active theme */
  --md-color-primary: ...;
  --md-color-on-primary: ...;
  --md-color-primary-container: ...;
  /* ... full light set ... */
}
[data-theme="dark"] {
  /* Same ~50 roles — dark scheme derived from the same source seed */
  --md-color-primary: ...;
  --md-color-on-primary: ...;
  /* ... full dark set ... */
}
```

This element wins the cascade for any `--md-color-*` token it declares
because it appears later in the stylesheet order than `tokens.css` (see
CONTEXT.md D-08 / PITFALLS.md Pitfall 2).

### Overridable Tokens (mode-dependent color roles)

The following `--md-color-*` tokens ARE included in the generated `<style>`:

| Role Family | Tokens |
|-------------|--------|
| Primary | `primary`, `on-primary`, `primary-container`, `on-primary-container`, `surface-tint` |
| Secondary | `secondary`, `on-secondary`, `secondary-container`, `on-secondary-container` |
| Tertiary | `tertiary`, `on-tertiary`, `tertiary-container`, `on-tertiary-container` |
| Error | `error`, `on-error`, `error-container`, `on-error-container` (fixed MD3 palette, included for completeness but not user-editable) |
| Surface / background | `background`, `on-background`, `surface`, `on-surface`, `on-surface-variant`, `surface-dim`, `surface-bright`, `surface-container-lowest`, `surface-container-low`, `surface-container`, `surface-container-high`, `surface-container-highest`, `surface-variant` |
| Outline / inverse | `outline`, `outline-variant`, `inverse-surface`, `inverse-on-surface`, `inverse-primary` |
| Scrim / shadow | `scrim`, `shadow` (kept stable for accessibility) |

### Mode-Invariant Tokens (NEVER overridden)

The following tokens are NEVER emitted in the generated `<style>` (see
`tokens.css:197-198` "radius/spacing/elevation/motion/font 为 mode-invariant"
and Phase 17 `CONTEXT.md D-08`):

| Token Family | Why Invariant |
|--------------|---------------|
| Radius (`--md-radius-xs` / `sm` / `md` / `lg` / `xl` / `full`) | Shape is a global design contract, not a theme property |
| Spacing (`--md-spacing-1` … `--md-spacing-8`) | 8dp grid is a project-wide invariant |
| Elevation (`--md-elevation-0` … `--md-elevation-5`) | **EXCEPTION:** see `Elevation in Dark Mode` below — dark mode MAY override 5 elevation tokens for shadow contrast against custom surface-tint |
| Motion (`--md-motion-duration-*`, `--md-motion-easing-*`) | Animation feel is a global design contract |
| Font (`--md-font-body`, `--md-font-display`) | Per REQUIREMENTS § "Out of Scope" — typography is a separate axis |
| Focus ring (`--md-focus-ring-outer`, `--md-focus-ring-inner`) | Accessibility critical, must remain stable |
| Nav height (`--md-nav-height`) | Layout structural |
| Tonal palettes (`--md-palette-{primary,secondary,tertiary,neutral,neutral-variant,error}-*`) | These are the *inputs* to derive roles; overriding them would create inconsistency. They are derived from the active seed but not exposed as runtime CSS vars. |

### Elevation in Dark Mode (FND-06)

Per CONTEXT.md D-09 / PITFALLS.md Pitfall 4, dark mode regeneration of the
5 `--md-elevation-*` tokens is REQUIRED to prevent the "flat dark UI" failure
mode. The generated `<style>` block for `[data-theme="dark"]` MAY emit:

```css
[data-theme="dark"] {
  /* Elevation regenerated against the active theme's surface-tint at low alpha
     (replaces tokens.css:163-167's hardcoded rgba(0,0,0,X) for dark mode) */
  --md-elevation-0: none;
  --md-elevation-1: 0 1px 2px 0 color-mix(in srgb, var(--md-color-surface-tint) 12%, transparent);
  --md-elevation-2: 0 1px 3px 0 color-mix(in srgb, var(--md-color-surface-tint) 14%, transparent);
  --md-elevation-3: 0 2px 6px 0 color-mix(in srgb, var(--md-color-surface-tint) 18%, transparent);
  --md-elevation-4: 0 4px 8px 0 color-mix(in srgb, var(--md-color-surface-tint) 22%, transparent),
                   0 1px 3px 0 color-mix(in srgb, var(--md-color-surface-tint) 14%, transparent);
  --md-elevation-5: 0 6px 12px 0 color-mix(in srgb, var(--md-color-surface-tint) 26%, transparent),
                   0 2px 4px 0 color-mix(in srgb, var(--md-color-surface-tint) 18%, transparent);
}
```

Light mode leaves the elevation tokens untouched (they remain as the
hardcoded `rgba(0,0,0,X)` from `tokens.css:163-167` — this is the existing
behavior and Phase 17 does not change light-mode elevation).

### Accent Reserved For (locked)

The accent role (`--md-color-primary`) is reserved for the same elements as
the existing v1.2 codebase. Phase 17 does NOT introduce new accent uses. The
specific elements that consume primary are:

- Header brand text (`家味` — `Header.css:36-43`)
- Avatar circle fill (`Header.css:79`)
- Header back icon + theme toggle + new palette icon (default IconButton color)
- Sidebar active-pill fill (`Sidebar.css:90`)
- UserHomePage quick-action icon container border (`styles.css:198`)
- /theme page "active" indicator pill on the selected card (the existing
  `secondary-container` pill style is reused; primary is NOT introduced here)
- /theme page reset IconButton (uses `on-surface-variant` per existing
  IconButton primitive; no new primary usage)

### Card Preview Color Source

The mini-UI preview inside each card (1 Card + 1 filled Button + 1 tonal
Button + 1 Chip + 4-step surface ramp) is rendered with **the card's own
theme tokens** scoped to a `<div data-fc-theme-scope={themeId}>` wrapper
(CONTEXT.md D-05). The wrapper receives a `<style>` rule scoped to itself
that emits the same `--md-color-*` override set as the global apply layer,
but only for its subtree. This is the same mechanism used by Material Theme
Builder's preview pane, formally enabled by MDN-documented CSS custom
property inheritance (see `FEATURES.md` § "How theme cards-as-previews render").

## Dynamic Theme Application

End-to-end flow showing the three independent paths that produce the same
end state: theme tokens applied to the document.

### Path A — FOUC Bootstrap (cold load, before React mounts)

```
┌──────────────────────────────────────────────────────────────────┐
│  Browser hits GET /                                             │
│  ┌─ <head> ─────────────────────────────────────────────────────┐│
│  │ <link rel="stylesheet" href=".../tokens.css">  ← parses      ││
│  │ <script>  (inline, blocking)                                ││
│  │   1. localStorage.getItem('fc_theme')                        ││
│  │      → set document.documentElement[data-theme]              ││
│  │   2. localStorage.getItem('fc_active_theme') (NEW, D-10)     ││
│  │      → JSON.parse → { sourceColors, variant }                ││
│  │      → call buildThemeCssSync(sourceColors, variant)         ││
│  │      → document.head.appendChild(<style id="fc-dynamic-theme">)│
│  │   3. (Bootstrap ends; </script>)                             ││
│  │ </script>                                                    ││
│  │ <script type="module" src="/src/main.jsx"></script>          ││
│  └──────────────────────────────────────────────────────────────┘│
│  First paint: themed colors visible immediately. No flash.       │
└──────────────────────────────────────────────────────────────────┘
```

**`buildThemeCssSync(sourceColors, variant)`** — a synchronous function
imported by the inline `<script>` through a chunked module (the
`theme-engine.js` module that ALSO exports `injectThemeCss` for
ThemeContext). Because the inline script runs BEFORE Vite hydration,
the module must be statically importable as ESM (no React, no JSX). Vite
bundles it into the main entry chunk (acceptable per CONTEXT.md §
"agent's Discretion" — MCU ~30KB gzip).

### Path B — ThemeContext Mount (after React mounts)

```
┌──────────────────────────────────────────────────────────────────┐
│  ThemeProvider mounts in App.jsx (inside SnackbarProvider)       │
│  ┌─ useState ──────────────────────────────────────────────────┐ │
│  │ activeTheme = initial: read from localStorage 'fc_active_    │ │
│  │   theme' fallback to PRESETS[0] (default green)              │ │
│  │ customThemes = []                                            │ │
│  └──────────────────────────────────────────────────────────────┘ │
│  ┌─ useEffect (mount once) ────────────────────────────────────┐ │
│  │ 1. injectThemeCss(buildThemeCss(activeTheme, currentMode))   │ │
│  │    → idempotent: replace innerHTML of #fc-dynamic-theme, or   │ │
│  │      insert if absent (D-08)                                │ │
│  │ 2. fire-and-forget GET /api/themes (D-15)                    │ │
│  │    → on success: setCustomThemes + reconcile by updatedAt    │ │
│  │    → on failure: showToast('无法同步主题...')  + keep cache  │ │
│  └──────────────────────────────────────────────────────────────┘ │
│  ┌─ useEffect (activeTheme change) ────────────────────────────┐ │
│  │ injectThemeCss(buildThemeCss(activeTheme, currentMode))     │ │
│  │ persist JSON to localStorage 'fc_active_theme' (D-05/08)    │ │
│  │ (NO FOUC: the <style> already exists; only innerHTML update)│ │
│  └──────────────────────────────────────────────────────────────┘ │
│  Value object memoized via useMemo (D-11, prevents drag-time     │
│  re-renders in Phase 18).                                       │
└──────────────────────────────────────────────────────────────────┘
```

### Path C — Light/Dark Toggle (orthogonal axis)

```
┌──────────────────────────────────────────────────────────────────┐
│  User clicks existing theme-toggle IconButton in Header         │
│  ┌─ handleToggleTheme (Header.jsx, unchanged) ──────────────────┐ │
│  │ 1. theme.toggleTheme() → set document.documentElement        │ │
│  │    [data-theme] = 'dark' or 'light'                            │ │
│  │ 2. setCurrentTheme(newTheme) → local React state for icon     │ │
│  └──────────────────────────────────────────────────────────────┘ │
│  ┌─ CSS cascade (NO JS re-application needed) ──────────────────┐ │
│  │ The existing <style id="fc-dynamic-theme"> already contains   │ │
│  │ :root {...} and [data-theme="dark"] {...} blocks. Flipping   │ │
│  │ the attribute on <html> causes the dark block to win the     │ │
│  │ cascade instantly. Zero JS re-apply. Zero flash. (D-09)      │ │
│  └──────────────────────────────────────────────────────────────┘ │
│  (Optional: ThemeContext can also subscribe to a custom event   │
│   to be notified of mode changes if it needs to swap elevation  │
│   tokens — but currently the inline <style> handles both modes.)│
└──────────────────────────────────────────────────────────────────┘
```

### Path D — User Clicks a Card on /theme

```
┌──────────────────────────────────────────────────────────────────┐
│  User taps a card on /theme                                     │
│  ┌─ card onClick (ThemeCard.jsx) ──────────────────────────────┐ │
│  │ 1. setActiveTheme(theme)   → ThemeContext re-renders         │ │
│  │ 2. ThemeContext useEffect fires:                             │ │
│  │    injectThemeCss(...)  +  localStorage[fc_active_theme] =  │ │
│  │ 3. (Preset case only) NO backend call — presets are          │ │
│  │    front-end constants (D-02).                               │ │
│  │ 4. (Custom theme case only) NO backend PUT — the *selection* │ │
│  │    is local-only; the theme itself was already saved at       │ │
│  │    creation time (Phase 18). Phase 17 is read-only on        │ │
│  │    custom themes; selecting one just updates localStorage.   │ │
│  │ 5. activeTheme prop changes → ThemeCard re-renders → the     │ │
│  │    newly selected card shows the "✓ 已选中" indicator.       │ │
│  └──────────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────┘
```

### The `<style id="fc-dynamic-theme">` Element (idempotent)

```js
// In theme-engine.js, used by all 3 paths:

function injectThemeCss(cssText) {
  let el = document.getElementById('fc-dynamic-theme');
  if (!el) {
    el = document.createElement('style');
    el.id = 'fc-dynamic-theme';
    document.head.appendChild(el);
  }
  el.textContent = cssText; // idempotent: replace innerHTML
}
```

This is the **single source of truth** for theme application. Three winners:

1. **Inline bootstrap** calls `injectThemeCss` before first paint (FOUC-safe).
2. **ThemeContext** calls `injectThemeCss` on mount and on `activeTheme` change.
3. **Light/dark toggle** does NOT call `injectThemeCss` — the CSS cascade
   handles it (D-09).

## Accessibility & Motion

### Touch Targets

- All IconButtons are 48dp × 48dp hit boxes (already enforced by
  `base.css:60-63` for `.md-icon-button`).
- The card itself is clickable (CONTEXT.md D-25) — the card's full
  area is a touch target. A card is `min-height: 220dp` (driven by the
  preview content) and full grid-column width, so even on the smallest
  mobile (≤420dp container) the card is well above 48dp × 48dp.
- The /theme page topbar reset button is 48dp × 48dp (IconButton primitive).
- The active indicator pill ("✓ 已选中") is **not** interactive — it is a
  status dot, not a button.

### Focus Indicators

- Header IconButtons (theme toggle, palette, avatar) preserve the existing
  `focus-visible: outline: var(--md-focus-ring-outer)` rules from
  `IconButton.css:51-54` and `Header.css:93-96`.
- Cards receive `focus-visible` outline identical to `.md-card--clickable`
  (`Card.css:46-49`) so keyboard users can navigate the grid.
- Tab order: Header right cluster (theme toggle → palette → avatar) is
  left-to-right; the page-level reset button is reachable via Tab after
  the last card in the grid.
- Skip-link: not added in Phase 17 (existing pattern — no skip link in
  the codebase today).

### ARIA

- Header entry button: `aria-label="选择主题"` (D-18).
- Page reset button: `aria-label="还原默认主题"`.
- Cards: `role="button"` (via existing `<Card onClick>` path in `Card.jsx:51`)
  and `aria-label={theme.name}` so screen readers announce the theme name
  on focus.
- Active indicator: `aria-live="polite"` on the active-indicator wrapper
  so a screen reader announces the active theme change after a click.
  Implementation: when the user clicks a card, the active indicator moves
  to the new card; a polite announcement of the new theme name is queued.
- Snackbar: `role="status" aria-live="polite"` (already set in
  `ToastContext.jsx:323`).
- Card preview scope: the `<div data-fc-theme-scope={themeId}>` wrapper
  has `aria-hidden="true"` so the preview mini-UI is NOT announced
  (otherwise screen readers would read the inner card title + button labels
  twice — once on the parent card and once on the preview).

### Reduced Motion

The /theme page does not introduce any new animations. Existing reduced-
motion rules in `base.css:67-70`, `Button.css:118-120`, and `Chip.css:129-132`
cover any inherited hover/focus transitions. Theme transitions (when
switching) are CSS-cascade repaints — no JS animation, no `transition`
property on body, no layout shift (CONTEXT.md D-09).

**Future Phase 18 hook:** The card preview's `align-items: stretch` on
the grid ensures cards in a row resize identically. When Phase 18 adds
real-time drag preview, the `useState` state will be in `ThemeContext` and
the value will be memoized to prevent whole-app re-renders per RESEARCH
PITFALLS.md § 7.

### Color Contrast (WCAG AA)

- All MD3 color roles are derived via the official MCU library
  (`@material/material-color-utilities`), which guarantees WCAG AA
  contrast for all body-text role pairs (PITFALLS.md Pitfall 3).
- The card-as-preview mini-UI uses the EXACT same primitives as the real
  app, so contrast is identical to the active theme in the main body.
- The `secondary-container` and `tertiary-container` chip backgrounds
  use the `on-secondary-container` and `on-tertiary-container` text
  colors — both are guaranteed AA by the MD3 spec.
- The active indicator pill uses `primary` background + `on-primary` text
  — guaranteed AA by the MD3 spec.

### Keyboard Navigation

- Tab order: Brand → Title (non-focusable) → Header theme toggle →
  Header palette (NEW) → Header avatar → (page content) → Page reset
  IconButton → Card #1 → Card #2 → ... → Card #N.
- Enter / Space on a focused card triggers click (existing `Card.jsx:36-43`
  `handleKeyDown`).
- Esc on the page returns to the previous page (browser default).
