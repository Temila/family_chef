## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → API | Untrusted JWT carries only user identity; request body must be validated by Pydantic schemas before service layer |
| Authenticated user → other user's data | Per-user ownership check at service layer (defense in depth: query WHERE clause + 403 on miss) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-01 | Spoofing | `/api/themes/*` endpoints | mitigate | All 4 endpoints require `get_current_user_from_token`; 12 test cases include `test_unauthenticated_create` asserting 401 without JWT |
| T-17-02 | Tampering | `source_colors` JSON column | mitigate | `SourceColors.field_validator` regex `^#[0-9a-fA-F]{6}$` raises 400 on malformed hex; `test_create_theme_invalid_hex` covers this |
| T-17-03 | Repudiation | CustomTheme mutation | accept | Server-side `updated_at` timestamp with `onupdate=sa.text("CURRENT_TIMESTAMP")` provides audit trail; deeper audit log out of scope for Phase 17 |
| T-17-04 | Information Disclosure | Cross-user theme access | mitigate | `list_themes` and `get_theme_by_id` use `WHERE user_id == current_user.id`; `update_theme` and `delete_theme` raise `ThemePermissionError → 403` on cross-user access; `test_list_themes_isolation` + 2 cross-user 403 tests verify |
