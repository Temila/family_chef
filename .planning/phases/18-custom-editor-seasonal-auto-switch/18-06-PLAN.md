<objective>
Fix the CSS cascade ordering bug in `injectThemeCss()` that causes the dynamic theme (`<style id="fc-dynamic-theme">`) to be overridden by Vite dev-mode CSS module injections (`tokens.css`, `styles.css`).

Purpose: Three UAT tests (6, 9, 12) all fail with the same root cause — the theme logic chain (`setActiveTheme` → `useEffect[activeTheme]` → `buildCssSync` → `injectThemeCss`) is correct, but the injected CSS is masked because `tokens.css` loads AFTER `fc-dynamic-theme` in dev mode, winning the cascade (same `:root` specificity, later source order wins). This makes ALL runtime theme changes invisible in dev mode.

Output: A one-line fix to `injectThemeCss` that ensures `fc-dynamic-theme` is always the last child of `<head>`, closing Tests 6, 9, and 12 simultaneously.

Root cause evidence: `.planning/debug/seasonal-no-color-change.md` (full investigation), `.planning/debug/save-not-applying.md`, `.planning/debug/card-click-no-apply.md`.
</objective>

In `frontend/src/theme/theme-engine.js`, locate the `injectThemeCss` function (lines 254-262). The function currently reads:

```js
export function injectThemeCss(cssText) {
  let element = document.getElementById('fc-dynamic-theme');
  if (!element) {
    element = document.createElement('style');
    element.id = 'fc-dynamic-theme';
    document.head.appendChild(element);
  }
  element.textContent = cssText;
}
```

Add ONE line — `document.head.appendChild(element);` — after the `element.textContent = cssText;` assignment (after line 261). `appendChild` on an element that is already a child of `document.head` MOVES it to the end of the children list, ensuring `fc-dynamic-theme` is always the LAST `<style>` in `<head>` and wins the CSS cascade over any later-injected Vite CSS modules.

The updated function should read:

```js
export function injectThemeCss(cssText) {
  let element = document.getElementById('fc-dynamic-theme');
  if (!element) {
    element = document.createElement('style');
    element.id = 'fc-dynamic-theme';
    document.head.appendChild(element);
  }
  element.textContent = cssText;
  document.head.appendChild(element);
}
```

Update the JSDoc comment above the function (lines 251-253) to document the cascade-ordering guarantee. Replace the existing comment with:

```js
/**
 * 创建或复用动态主题样式节点。每次调用都重新 appendChild 到 <head> 末尾，
 * 确保 fc-dynamic-theme 始终是 <head> 最后一个 <style>，在 CSS 级联中
 * 胜出（同特异性 :root 选择器，后源序优先）。修复 Vite dev 模式下
 * tokens.css 注入到 fc-dynamic-theme 之后导致动态主题被覆盖的问题。
 */
```

Do NOT change any other function, export, or constant in this file. The change is exactly one new line plus the comment update.

Gap reason (from debug session seasonal-no-color-change.md): In Vite dev mode, `tokens.css` and other CSS modules are injected as `<style>` tags at the END of `<head>` by Vite's client runtime, AFTER the FOUC bootstrap created `fc-dynamic-theme`. Both use `:root` with specificity (0,0,1); source order determines the winner. `tokens.css` loads later → wins → overrides dynamic theme variables. The `appendChild` call on every `injectThemeCss` invocation moves `fc-dynamic-theme` to be the last child, reclaiming cascade precedence.
