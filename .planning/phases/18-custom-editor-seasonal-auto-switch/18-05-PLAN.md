<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authenticated user → theme page/settings/editor navigation | User clicks and route query values select actions and records. |
| theme card action → authenticated CRUD API | Delete and update identifiers cross the existing JWT API boundary. |
| theme name/record → rendered card DOM | Server-returned names and metadata are rendered in card labels and accessible attributes. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-14 | Elevation of Privilege | ThemePage card actions | mitigate | Keep `seasonEnabled` enforcement in ThemeContext and use page callbacks only for navigation/no-op; cards never bypass the context with direct global apply calls. |
| T-18-15 | Tampering | custom delete action | mitigate | Render delete only for `kind === 'custom'`, require a Chinese confirmation, call the JWT-scoped `api.deleteTheme`, refresh the server list, and restore a safe active preset if the deleted theme was active. |
| T-18-16 | Cross-Site Scripting | theme names and route queries | mitigate | React renders names as text, route query values are restricted to numeric custom IDs or known preset IDs before navigation, and button events stop propagation without HTML string construction. |
| T-18-17 | Denial of Service | settings toggle and seasonal apply | mitigate | Context actions remain synchronous, finite, and cache-gated; the settings page does not create network polling or repeated mount effects. |
| T-18-SC | Tampering | frontend package graph | mitigate | Use only dependencies approved in Plan 18-02 and run the full frontend lint/build/token checks after route/card wiring. |
</threat_model>
