## Directory Purposes

**`backend/app/`:**
- Purpose: All backend application source code
- Contains: Models, schemas, routers, services, utilities, integrations, middleware
- Key files: `main.py` (app entry), `config.py` (settings), `database.py` (DB setup)

**`backend/app/models/`:**
- Purpose: SQLAlchemy ORM table definitions
- Contains: One file per domain entity
- Key files: `user.py`, `dish.py`, `order.py`, `ingredient.py`, `category.py`, `preference.py`, `favorite.py`, `schedule.py`, `log.py`

**`backend/app/schemas/`:**
- Purpose: Pydantic V2 request/response validation models
- Contains: Schema files mirroring model structure plus `common.py` for shared schemas
- Key files: `user.py`, `dish.py`, `order.py`, `ingredient.py`, `category.py`, `preference.py`, `favorite.py`, `common.py`

**`backend/app/routers/`:**
- Purpose: FastAPI route handlers (HTTP layer)
- Contains: One file per API domain
- Key files: `auth.py` (also exports auth dependencies), `dishes.py`, `orders.py`, `users.py`, `ingredients.py`, `categories.py`, `favorites.py`, `preferences.py`, `chefs.py`, `admin.py`, `feishu.py`, `tools.py`, `upload.py`

**`backend/app/services/`:**
- Purpose: Business logic layer, database query building
- Contains: One file per API domain plus specialized services
- Key files: `auth_service.py`, `dish_service.py`, `order_service.py`, `user_service.py`, `ingredient_service.py`, `category_service.py`, `chef_service.py`, `favorite_service.py`, `preference_service.py`, `admin_service.py`, `dashboard_service.py`, `ingredient_extractor.py`, `smart_ingredient_extractor.py`

**`backend/app/utils/`:**
- Purpose: Shared utility functions
- Contains: `security.py` (bcrypt/JWT), `pagination.py`, `response.py` (API response models), `pinyin.py`

**`backend/app/integrations/`:**
- Purpose: External service client implementations
- Contains: `feishu.py` — Feishu Bot API client (tenant token, card messages)

**`backend/app/middleware/`:**
- Purpose: Cross-cutting middleware functions
- Contains: `logging.py` — `log_action()` for system audit trail

**`backend/tests/`:**
- Purpose: Test suite for backend
- Contains: `conftest.py` (test fixtures), 22 test modules covering all domains
- Key files: `conftest.py`, `test_auth.py`, `test_dishes.py`, `test_orders.py`, `test_ingredients.py`

**`frontend/src/pages/`:**
- Purpose: Route-level React page components
- Contains: 20 page components organized by user role
- Key files: `LoginPage.jsx`, `UserHomePage.jsx`, `AdminDishesPage.jsx`, `ChefOrdersPage.jsx`, `OrderPage.jsx`

**`frontend/src/components/`:**
- Purpose: Reusable UI components
- Contains: `Sidebar.jsx` (desktop navigation), `DishCard.jsx`, `Header.jsx`, `BottomBar.jsx` (mobile nav), `ThemeToggle.jsx`, `Badge.jsx`, `Loading.jsx`, `EmptyState.jsx`

**`frontend/src/contexts/`:**
- Purpose: React Context providers for global state
- Contains: `AuthContext.jsx` (user/auth), `CategoriesContext.jsx` (cached categories), `ToastContext.jsx` (notifications)

**`frontend/src/api/`:**
- Purpose: Backend API client
- Contains: Single `client.js` file — `ApiClient` class wrapping all endpoints

**`frontend/src/auth/`:**
- Purpose: Token and user persistence
- Contains: Single `index.js` file — localStorage-based auth manager

**`docker/`:**
- Purpose: Container deployment
- Contains: `Dockerfile` (multi-stage build), `docker-compose.yaml` (production config)

**`scripts/`:**
- Purpose: Startup automation
- Contains: `run-dev.sh` (development), `run.sh` (production)

## Naming Conventions

**Files:**
- Backend Python files: `snake_case.py` — e.g., `order_service.py`, `auth_service.py`
- Backend model files: Single entity `snake_case.py` — e.g., `user.py`, `dish.py`, `order.py`
- Backend schema files: Match model names — e.g., `user.py`, `dish.py`, `order.py`
- Backend router files: Pluralized domain name — e.g., `dishes.py`, `orders.py`, `users.py`
- Frontend page files: `PascalCasePage.jsx` — e.g., `UserHomePage.jsx`, `AdminDishesPage.jsx`
- Frontend component files: `PascalCase.jsx` — e.g., `DishCard.jsx`, `ThemeToggle.jsx`
- Frontend context files: `PascalCaseContext.jsx` — e.g., `AuthContext.jsx`, `ToastContext.jsx`
- Frontend utility/hook files: `camelCase.js` — e.g., `usePendingOrderCount.js`, `client.js`
- Test files: `test_*.py` — e.g., `test_auth.py`, `test_dishes.py`

**Directories:**
- Backend: `snake_case/` — `models/`, `schemas/`, `routers/`, `services/`, `utils/`, `integrations/`, `middleware/`
- Frontend: `kebab-case/` or `camelCase/` — `pages/`, `components/`, `contexts/`, `api/`, `auth/`, `hooks/`, `utils/`, `css/`

**Python Classes:**
- Models: `PascalCase` — `User`, `Dish`, `Order`, `DishIngredient`
- Services: `PascalCaseService` — `AuthService`, `DishService`, `OrderService`
- Schemas: `PascalCaseRequest`/`PascalCaseResponse` — `DishCreate`, `DishUpdate`, `DishDetailResponse`, `PageResponse[T]`
- Module-level singletons: `snake_case_service` — `auth_service`, `dish_service`, `order_service`

**API Routes:**
- Prefix: `/api/{domain}` — `/api/dishes`, `/api/orders`, `/api/auth`
- Nested resources: `/{parent}/{id}/{child}` — `/dishes/{dish_id}/status`, `/dishes/{dish_id}/chef-publish`
- Status updates: `PUT /{resource}/{id}/status`
- Plural domain names in URLs: `/api/dishes`, `/api/orders`, `/api/users`

**Database Tables:**
- Table names: `snake_case` plural — `users`, `dishes`, `orders`, `order_items`, `dish_ingredients`
- Join tables: `{entity}_{entity}` — `dish_ingredients`, `dish_categories`, `dish_chefs`
- Column names: `snake_case` — `user_id`, `created_at`, `password_hash`, `order_no`

## Where to Add New Code

**New API Endpoint:**
1. Create/extend service in `backend/app/services/{domain}_service.py`
2. Create/extend schema in `backend/app/schemas/{domain}.py`
3. Create/extend route in `backend/app/routers/{domains}.py`
4. Register router in `backend/app/main.py` (if new file)
5. Add API method in `frontend/src/api/client.js`
6. Create/update page in `frontend/src/pages/{PageName}.jsx`
7. Add route in `frontend/src/App.jsx`

**New Database Model:**
1. Create `backend/app/models/{entity}.py` — extend `Base` from `database.py`
2. Export from `backend/app/models/__init__.py`
3. Add Alembic migration: `cd backend && uv run alembic revision --autogenerate -m "description"`
4. Create corresponding schema in `backend/app/schemas/{entity}.py`

**New Frontend Page:**
1. Create `frontend/src/pages/{PageName}.jsx`
2. Import in `frontend/src/App.jsx`
3. Add `<Route>` with `ProtectedRoute` wrapper and role requirements
4. Add link in `frontend/src/components/Sidebar.jsx` (if navigation needed)

**New Shared Utility:**
- Backend: `backend/app/utils/{name}.py`
- Frontend: `frontend/src/utils/index.js`

**New External Integration:**
1. Create `backend/app/integrations/{service}.py` — client class as singleton
2. Call from relevant service method (use lazy import if circular dependency risk)

**New Test File:**
- Create `backend/tests/test_{domain}.py`
- Import fixtures from `backend/tests/conftest.py`
